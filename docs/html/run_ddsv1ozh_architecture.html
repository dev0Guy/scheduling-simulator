amber-dragon-310 — gated dual attention at n_machines=1

W&B run cxtxjusj (wandb.ai/…/cxtxjusj). Same dual-attention architecture as run ddsv1ozh below, but each cross-attention branch is now gated by a learnable per-channel scale initialized to zero (LayerScale), so the branch starts as a no-op and only grows where training finds it earns its keep, instead of being folded in at full strength from step one. Trained for 1,000,000 steps (half the budget of every other compared variant, on the theory that most of the earlier win-rate gains showed up well within that budget).

The task

A cluster runs n_machines identical machines and receives n_jobs jobs over the course of an episode. Each job arrives at some tick, needs size ticks of uninterrupted machine time to finish, and fully occupies whichever machine runs it — no sharing, no preemption. Every tick, the scheduler either allocates one pending job to a free machine or does nothing. The objective is to minimize total flow time: the sum, across every job, of the time it spends waiting plus running.

This is 1 | rj | ΣCj in scheduling-theory notation when there's a single machine — single machine, jobs with release dates, non-preemptive, minimize total completion time — and its multi-machine generalization once n_machines > 1. The strong classical baseline is Shortest-Job-First (SJF): whenever the machine frees up, run the smallest job currently waiting. It's provably near-optimal in the single-machine case, which is why it's a hard target to beat.

The network

Two encoders read the raw state — one per job, one per machine — then a dual attention stage lets jobs compare against each other, lets machines compare against each other, and lets the two sides read one another's state directly, before anything is pooled into a global summary or scored into an action.

Multi-head attention, in detail

Every attention block in the diagram above — job self-attention, machine self-attention, and both cross-attention directions — is the same mechanism from "Attention Is All You Need" (Vaswani et al., 2017), nn.MultiheadAttention with embed_dim=256 and num_heads=4 (64 dims per head). What differs between blocks is only which set of vectors plays queries and which plays keys/values.

The gate did what it was added to do: cxtxjusj has the lowest SJF win-rate and the highest tie rate of any dual-attention variant, confirming the "more decisive, not more accurate" failure mode from ddsv1ozh (where both win-rate and loss-rate rose together) is fixed by letting training grow the cross-attention contribution gradually instead of injecting it at full strength from step one. What's still open: PPO's own win-rate and mean reward margin here are also below g231w4jg, not just below ddsv1ozh — and this run only received half the training steps (1M vs. 2M) of every other variant it's compared against, so it isn't yet a fair test of the gated architecture's ceiling. A matched-steps (2M) rerun is needed to tell "the gate caps upside" apart from "the gate is undertrained."

Why this run, specifically

The dual attention architecture is adapted from "Flexible Job Shop Scheduling via Dual Attention Network Based Reinforcement Learning" (Wang et al., arXiv:2305.05119) and was first tested at n_machines=2 (run rpw3vr25), the only setting where the machine-attention half can do real work. That run was stopped before completion to first get a clean, controlled read at the already-validated n_machines=1 config, which produced ddsv1ozh: the architecture helped in neither direction cleanly, growing both PPO's win rate and its loss rate against the current best (g231w4jg). This run (cxtxjusj) adds a LayerScale gate (learnable per-channel scale, init 0) around each cross-attention branch so the network only takes on the new signal where it actually earns its keep, instead of absorbing it at full strength immediately — see Results above.
