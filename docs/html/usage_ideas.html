How to help the model understand usage

One shared example is used in every section so the ideas can be compared. One machine, capacity 255 on 3 resources (R0, R1, R2).

The shared example

A job R is already running and will finish in 4 ticks. Three jobs are pending. Usage is [R0, R1, R2].

1. Pair features for every (job, machine) biggest payoff

Instead of making the network guess whether a job fits, give it the numbers directly, computed from the machine's free-capacity timeline.

JobFits nowDelay until it fitsHeadroom after placing [R0,R1,R2]Dominant sharePacking score
Ayes0[27, 63, 127]0.500.76
Bno4 (R ends)–1.00–
Cyes0[63, 127, 63]0.500.69

Why it helps: B cannot start for 4 ticks no matter what. The model can see that and choose to run A or C in the meantime, knowing exactly how long B will wait. Dominant share is the largest of usage ÷ capacity across resources. The packing score is usage · free normalised: the higher it is, the tighter the job fills the free space.

2. A dynamic machine embedding

Today the actor uses a fixed per-machine vector (nn.Embedding) that never changes, so it carries no state. The idea is to encode the machine's free-capacity grid (3 resources × 10 ticks) with the same per-row encoder used for jobs.

Free capacity grid the encoder would read (darker = less free):

Before: machine vector = a constant, the same every tick.

After: machine vector = f(grid), so it changes as jobs start and finish. The final layer starts at zero, so training begins where it does now.

3. Job–job compatibility matrix

For every pair of jobs, mark whether they fit together on an empty machine (summed usage ≤ 255 on every resource). This goes into the job self-attention as a bias, so attention between compatible jobs is easier.

ABC

B✗ R0: 355–✗ R0: 319

Why it helps: it shows at a glance that A and C can run side by side and B cannot share with anything. Then the model can plan: run A and C together, B after.

4. Usage in the job encoder

Today the job encoder input is [status, size, wait, ttl, arrival]. Usage only enters later through the fit attention. The change is to add usage and headroom to the input.

Input for job A
Now[status=pending, size 3, wait 0, ttl 3, arrival 0]
After[status=pending, size 3, wait 0, ttl 3, arrival 0, usage 0.39, 0.50, 0.25, headroom 0.11, 0.25, 0.50]

Why it helps now: this was removed earlier because usage was identical on all resources, so it was redundant with size. With different values per resource, it carries real information.

5. Start from SJF, then learn most reliable

Add a fixed prior to the action logits: −α · size for jobs that fit and a large penalty for jobs that don't. At the start of training the policy behaves like SJF, and PPO only has to learn where to deviate.

Left bar of each pair: random start (uniform). Right bar: with the prior (α = 0.5, skip logit −3, doesn't-fit penalty −5). C, the shortest job that fits, gets 57%. B, which doesn't fit, gets almost nothing.

6. Imitation warm-start optional

Same goal as 5, different method: pre-train the policy by supervised learning to copy a heuristic, then continue with PPO.

Trade-off: it needs an extra training stage and a baseline to copy. The prior in 5 gives most of the benefit with a few lines of code.
