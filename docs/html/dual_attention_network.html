Cluster Scheduling Simulator · Architecture

A dual attention network for job & machine scheduling

The task

A cluster runs n_machines identical machines and receives n_jobs jobs over the course of an episode. Each job arrives at some tick and needs size ticks of machine time to finish. Machines are no longer exclusive: each job now claims a random fraction of a machine's capacity (10–50%), so multiple jobs can run concurrently on the same machine as long as their combined usage fits (bin-packing), not just one job at a time. Every tick, the scheduler either allocates one pending job to a machine with room or does nothing. The objective is to minimize total flow time: the sum, across every job, of the time it spends waiting plus running.

This is 1 | rj | ΣCj in scheduling-theory notation when there's a single machine — single machine, jobs with release dates, non-preemptive, minimize total completion time — and its multi-machine generalization once n_machines > 1. The strong classical baseline is Shortest-Job-First (SJF): whenever a machine has room, run the smallest job currently waiting. It's provably near-optimal in the single-machine, exclusive-occupation case, which is why it's a hard target to beat even once concurrent packing is introduced.

The network

Two encoders read the raw state — one per job, one per machine — then a dual attention stage lets jobs compare against each other, lets machines compare against each other, and lets the two sides read one another's state directly, before anything is pooled into a global summary or scored into an action.

Why this exists

Adapted from "Flexible Job Shop Scheduling via Dual Attention Network Based Reinforcement Learning" (Wang et al., arXiv:2305.05119). Before this change, machine choice came from a static per-machine identity vector with no awareness of load; job embeddings never saw machine state at all. The dual cross-attention block is the one addition that lets both sides read each other's live state before a single (machine, job) pair gets scored.

Gated, not full-strength. The first version (run ddsv1ozh) folded each cross-attention branch in immediately at full strength and made the policy more decisive without being more accurate — both its win rate and loss rate vs. SJF rose together. Each branch is now scaled by a learnable per-channel gate initialized to zero (LayerScale, Touvron et al. 2021): embeddings + GATE × cross_attn_output, with GATE = 0 at init. Training starts equivalent to the no-cross-attention baseline and only grows a gate where that signal actually earns its keep.

Job input added: usage. The cluster generator changed so each job now claims a random fraction of a machine's capacity (10–50%, broadcast identically across every resource/time cell) instead of always claiming full capacity — so multiple jobs can genuinely run concurrently on one machine (bin-packing), not just sequentially. A first PPO run trained on this new generator lost to SJF in 97.42% of episodes (run h0vwcu5e) despite training cleanly, because nothing in the feature set told the policy how much of a machine a job would occupy — SJF doesn't need that (it ignores occupancy by construction), but a policy reasoning about concurrent packing cannot function without it. Fixed by adding usage as a per-job feature: a single scalar read from one cell of the job's usage matrix (any cell works, since the value is now uniform across the whole matrix), normalized by max_capacity.
